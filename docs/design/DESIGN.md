# Дизайн-контракт: Context Lens & Token Guard

## 1. User Surfaces (Пользовательские поверхности)

### 1.1. Индикатор сессии (Header Chip & Popover)
- **Слот**: `conversation.session.header.utilities`
- **ID компонента**: `dsh-context-lens-header-chip`
- **Порядок (`order`)**: `7` (располагается в группе мониторинга рядом с `dsh-key-rotation` [order: 6] и `dsh-cost-meter` [order: 10]).
- **Роль**: Информирование пользователя о степени экономии контекстного окна (в %) и текущем состоянии сессионного бюджета токенов, с возможностью детального просмотра по клику.

### 1.2. Карточка настроек (Settings Plugin Card)
- **Слот**: `settings.plugin.item`
- **Key**: `@goodandready/dsh-context-lens`
- **Роль**: Управление режимом сжатия (`raw`, `balanced`, `aggressive`), глубиной AST-скелетонизации, лимитом бюджета токенов и интерактивным предпросмотром сжатия логов.

### 1.3. Вкладка боковой панели (BetterSidebar Tab)
- **ID вкладки**: `dsh-context-lens:tab`
- **Роль**: Альтернативная поверхность в BetterSidebar для просмотра расширенной истории операций сжатия и бюджета.

## 2. Components And States (Компоненты и состояния)

### 2.1. Чип в шапке беседы (`HeaderChip`)
- **Базовый стиль**:
  - Компактная нативная кнопка-чип высотой ~24px с закруглением `borderRadius: 999px` или `8px`.
  - Токены: `var(--dsw-alias-bg-layer-2)`, цвет текста `var(--dsw-alias-label-secondary)`, граница `1px solid var(--dsw-alias-border-l2)`.
  - Иконка `◐` и текстовый лейбл.
- **Состояния**:
  - `Initial / Empty`: пока сжатий нет (`savedTokens === 0`), отображается `◐ Lens`. Индикатор никогда не скрывается, пользователь всегда видит присутствие плагина.
  - `Active / Compressed`: при наличии сэкономленных токенов отображается `◐ <savedPercent>%` (например, `◐ 85%`).
  - `Warning / Low Budget`: при расходе сессионного бюджета > 90% добавляется предупреждающий символ `⚠`, граница и текст окрашиваются в `#d73a4a` (или `var(--dsw-alias-color-danger)`).
  - `Open / Active`: чип подсвечивается при открытом поповере.

### 2.2. Выпадающая панель (`HeaderPopover`)
- **Позиционирование**: Абсолютное под чипом (`top: 'calc(100% + 6px)'`, `right: 0`), `zIndex: 1000`.
- **Стилизация**: `background: 'var(--dsw-alias-bg-layer-3)'`, тень `boxShadow: '0 8px 24px rgba(0,0,0,0.25)'`, скругление `10px`, граница `1px solid var(--dsw-alias-border-l2)`, ширина `260px..300px`.
- **Содержимое**:
  1. **Заголовок**: `Context Lens` + иконка `◐`.
  2. **Метрики сжатия**:
     - Сэкономлено токенов: `Saved <N> tk (<savedPercent>%)`.
     - Количество вызовов: `<calls> ops`.
  3. **Шкала бюджета токенов**:
     - Текст: `Budget: <used> / <limit> (<budgetPercent>%)`.
     - Прогресс-бар высотой `6px`, фон `var(--dsw-alias-bg-layer-1)`, полоса `var(--dsw-alias-label-primary)` (при `lowBudget` — `#d73a4a`).
  4. **История последних операций**:
     - Последние 3 сжатия с дельтой токенов и превью пути/лога.
  5. **Действия**:
     - Кнопка «Обновить» (`Refresh`).
- **События**: Закрытие по клику вне области (Click-outside listener).

## 3. User Flows (Пользовательские сценарии)

1. **Первый запуск / Новая сессия**:
   - Пользователь открывает чат.
   - В шапке отображается `◐ Lens`.
   - Клик на чип открывает поповер со статусом `No data yet` и шкалой бюджета `0 / 100k (0%)`.
2. **Рабочая сессия агента**:
   - Агент запускает компрессию логов или AST-скелетонизацию кода.
   - Чип обновляется по периодическому поллингу (интервал 4-5 сек) и показывает актуальный процент экономии, например `◐ 78%`.
   - Пользователь нажимает на чип и видит детальную разбивку: сколько токенов срезано, сколько операций выполнено, превью последних сжатий.
3. **Исчерпание бюджета (Token Budget Guard)**:
   - Если суммарный объем токенов сессии превышает 90% от лимита, чип окрашивается в предупреждающий красный/янтарный цвет: `◐ 92% ⚠`.
   - Пользователь видит предупреждение о скором исчерпании контекстного окна.

## 4. Locked Design Decisions (Зафиксированные решения)

1. **Слот**: `conversation.session.header.utilities` — строго зафиксирован как единственное легитимное место для мониторов и телеметрии сессии.
2. **Никакого полного скрытия**: чип всегда присутствует в шапке (в отличие от старого ошибочного `return null`).
3. **Только нативные CSS-переменные DSH**: `--dsw-alias-bg-layer-*`, `--dsw-alias-label-*`, `--dsw-alias-border-*`.


## 5. Client Services & Dependency Safety (v0.1.13)

1. **Cordis Context Invariants**: Клиентская половина никогда не обращается напрямую к свойствам сервисов `ctx.<service>`, не объявленным в `module.exports.inject`.
2. **Опциональный BetterSidebar**: Регистрация вкладки `dsh-context-lens:tab` выполняется исключительно через `ctx.inject(['betterSidebar'], (sctx) => ...)` внутри блока проверки `typeof ctx.inject === 'function'`.
3. **Фолбэк настроек**: Обращение к `_ctx.settingsScope` обернуто в try/catch для предотвращения ошибок при работе под строгим прокси контекста.


## 6. Stability, Localization & Multiline AST (v0.1.14)

1. **Динамическая локализация**: Компоненты `HeaderChip`, `LensTab` и `StatusPanel` используют `getActiveLocale(ctx)`, извлекая актуальный снимок языка из `ctx.locale.getSnapshot().active`.
2. **Адаптивный сетевой поллинг**: Опрос эндпоинта `/dsh-context-lens/status` в `HeaderChip` выполняется с интервалом 15 секунд при закрытом поповере, 4 секунды при открытом, и полностью замораживается при скрытии страницы (`document.visibilityState === 'hidden'`).
3. **Многострочные сигнатуры**: `skeletonizer.js` накапливает строки до терминаторов блоков (`{`, `=>`, `:`), корректно сохраняя длинные типизированные аргументы и возвращаемые промисы без разрушения структуры кода.
4. **Инструмент сброса**: Инструмент `context_lens_reset` позволяет сбросить глобальные счётчики экономии и историю для чистой сессионной телеметрии.


## 7. Dual Sidebar Compatibility (v0.1.15)

1. **Нативная правая боковая панель DSH (0.1.5-alpha.1+)**:
   - Двухэтапная регистрация:
     - Декларация типа через `ctx.sidebarRightTabs.register({ id: "@goodandready/dsh-context-lens", kind: "context-lens", priority: "extension", title: () => "Lens", guide: [...] })`.
     - Монтирование компонента вкладки через слот `sidebar.right.pane.tab` с ключом `@goodandready/dsh-context-lens`.
2. **Легаси BetterSidebar**:
   - Регистрация вкладки `dsh-context-lens:tab` через адаптер `ctx.inject(["betterSidebar"], ...)` сохранена для обратной совместимости со старыми профилями.
3. **Бесконфликтное сосуществование**:
   - При одновременной активности обеих поверхностей используются детерминированные, независимые идентификаторы (`@goodandready/dsh-context-lens` для native и `dsh-context-lens:tab` для legacy).
   - Рендеринг и состояние не конфликтуют.
4. **Фолбэк при отсутствии боковых панелей**:
   - При отсутствии обеих панелей плагин инициализируется без ошибок, сохраняя полную функциональность карточки настроек и чипа в шапке беседы.

## 8. ClineBot Unified Style & UI Robustness (v0.1.16)

1. **Единая дизайн-система с dsh-clinebot**:
   - Внедрена общая CSS-система классов с префиксом `.cl-` (`.cl-section-card`, `.cl-section-header`, `.cl-stat-grid`, `.cl-stat-box`, `.cl-bar-box`, `.cl-btn`, `.cl-btn-primary`, `.cl-badge`, `.cl-banner-warn`, `.cl-error-box`).
   - Использование исключительно токенов дизайн-системы DeepSeek Harness (`var(--dsw-alias-...)`).
   - Статистические блоки в виде адаптивной сетки `cl-stat-grid` с раздельным выделением крупных числовых значений и подписей.
   - Скругленный прогресс-бар типа «pill» со скруглением `999px` и динамической сменой акцентного цвета при превышении порога бюджета.
2. **Изоляция сбоев (ErrorBoundary)**:
   - Все визуальные компоненты (`LensTab`, `PluginCard`, `StatusPanel`) обернуты в нативный `ErrorBoundary`.
   - В случае ошибки рендеринга отображается локальный предупреждающий блок с текстом ошибки и кнопкой повторной попытки («Retry»), предотвращая размонтирование родительского дерева и возникновение React Error 310.
3. **Реактивная синхронизация настроек**:
   - Поддержка чтения снимка настроек через `scope.getSnapshot()` при наличии и автоматическая реактивная подписка через `scope.subscribe()` с очисткой при размонтировании.
4. **Защита от невалидных входных данных**:
   - Все методы сжатия (`compressLog`), скелетонизации (`skeletonize`) и трекинга устойчивы к вызовам с `null`, `undefined`, числами, пустыми объектами и некорректными типами.
